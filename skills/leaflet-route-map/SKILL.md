# Interactive Route Maps (Leaflet)

Build a self-contained HTML route map: real road geometry per leg, numbered stop
markers with popups, a side legend with timing/narrative, and stat chips (total
distance, drive time, arrival window). Viewer needs internet for the unpkg CDN
and OSM tiles. Start from `templates/leaflet_route_map.html` (fill placeholders
rather than writing HTML from scratch).

For single geocode/distance/direction queries the `maps` skill is lighter —
this skill is for the *visual multi-stop map* deliverable.

## Procedure

1. **Geocode every stop** with Nominatim (`/search?format=jsonv2`, one request
   every ~1.1s). On a miss retry with alternate spellings — local-language
   names often resolve when English does not. Save coordinates to a JSON file
   early so progress survives context compaction.
2. **Route each leg with OSRM**: `https://router.project-osrm.org/route/v1/driving/{lon},{lat};{lon},{lat}?overview=full&geometries=geojson` for each
   consecutive stop pair. Keep the real geometry and per-leg km/min — never
   straight lines. Downsample geometry to ~150 points per leg before embedding.
3. **Verify corridors on long highway legs**: check the leg geometry passes
   near an expected intermediate point (a known city or junction). OSRM can
   quietly detour around the intended highway, producing plausible-but-wrong
   routes on ~200 km legs.
4. **Fill the template**: replace `__LEGS__`, `__COLORS__`, `__STOPS__`,
   `__LEGEND__` and the stat placeholders with JSON. If the source is a user
   document, keep its numbering, times, and wording verbatim — do not
   renumber or 'fix' the narrative.
5. **Verify before opening** (this is where most failures hide):
   - Parse each injected const back with `json.loads` and assert shape
     (e.g. `LEGS[0].keys() == {name,km,min,geo}` and `STOPS[0].keys() == {id,lat,lon,n,name,t,d}`).
   - Open in the browser and check DOM facts: `typeof LEGS !== 'undefined'`,
     `document.querySelectorAll('.marker').length` matches stop count,
     `.leaflet-tile` count > 0, legend block count > 0. A screenshot alone
     can hide a silently dead script.

## Pitfalls

- **OSRM is `[lon,lat]`, Leaflet is `[lat,lon]`** — swap when embedding, or
  the route renders as a line across the ocean.
- **String-replacement into the template is unchecked**: if later JS expects
  `LEGS[i].geo` but raw coordinate arrays were injected, the page's entire JS
  dies silently — blank map, empty legend — while the on-disk file looks
  perfectly fine (title, styles, static divs all correct). Always parse the
  injected JSON back and verify shape before the browser step; this is the
  single most expensive failure mode for this task.
- **Stale `file://` tabs**: the browser can keep an old cached version (old
  title, old DOM). If DOM reads disagree with the on-disk file, reload with
  `?v=<timestamp>` before concluding the file is broken.
- **Corridor drift on long legs**: verify each long leg against an expected
  intermediate point; a 200 km leg that avoids the intended highway looks
  fine in the stats but is wrong on the map.
- **Source-document RTL text**: user-provided route/travel documents (often
  PDFs generated by chat apps) frequently have a garbled Hebrew/Arabic text
  layer — letters present but reversed or mixed with placeholder glyphs. If
  extracted text shows that, do NOT quote it: render pages at ~170 dpi
  (`pymupdf` `get_pixmap(dpi=170)`) and transcribe with `vision_analyze`,
  restoring RTL names from context, and tell the user which parts were
  reconstructed. Keep numbers/times/structure verbatim; only the script
  itself gets repaired.
- Write the map to the user's documents drive with a versioned name (e.g.
  `*_v2.html`), not a shared temp path, and deliver via `MEDIA:` so the
  desktop app can open it.

## Verification

```python
import re, json
s = open(out_path, encoding='utf-8').read()
for var in ("LEGS","STOPS","LB"):
    m = re.search(rf"const {var} = (.*?);\n", s, re.S)
    data = json.loads(m.group(1))
    print(var, len(data), list(data[0].keys()))
```

Then browser DOM checks per step 5. All counts matching the input data is
the completion bar — before claiming the map works.

## PDF Deliverable (when the artifact must be a file, not an HTML page)

Standing user standard for this class: a schematic/diagram 'map' from a source
document is rejected — the PDF must show a **real cartographic basemap**
(actual OSM tiles) with the route overlaid, the source document's legend
**verbatim**, and a Waze GPS table (decimal `lat, lon` + DMS + cumulative km
per stop, hot stops highlighted).

1. **Do not composite OSM tiles in Python unless verified**: fetch one tile
   and check it actually contains data — a uniform single-color tile means the
   fetch was intercepted/placeholdered (happens with plain urllib). If so, do
   NOT hand-assemble the basemap in PIL; render the Leaflet page in the
   browser instead — the browser loads the same tiles fine.
2. **High-res full-page map image via CDP screenshot** (reliable even when
   `file://` tabs look stale):
   ```python
   cdp("Emulation.setDeviceMetricsOverride", width=W, height=H, deviceScaleFactor=2)
   shot = cdp("Page.captureScreenshot", format="png", captureBeyondViewport=True)  # base64 -> save
   ```
   Size the viewport to the route's bounding box (tall/narrow is fine for a
   north-south route); deviceScaleFactor=2 for sharpness. Verify the PNG with
   vision before embedding (marker overlap, clipped labels are the usual
   fixes: manual label offsets, separate start/finish markers).
3. **Build the PDF with pymupdf** (map page A3, legend A4 portrait,
   GPS table A4 landscape):
   - Register fonts on **every page**: `p.insert_font(fontname=..., fontfile=...)`
     per page — fonts do NOT carry across pages; reusing a fontname from page 1
     raises `need font file or buffer`.
   - Measure/wrap with `fitz.Font(fontfile=...).text_length(text, fontsize=s)`
     (standalone, page-independent) instead of the page-bound text-length API.
   - Write the build script to disk with `write_file` (split long scripts into
     parts run in sequence) and run it with the Hermes venv python
     (`<hermes home>\hermes-agent\venv\Scripts\python.exe` — it has pymupdf).
     Very long inline `execute_code` payloads can arrive truncated mid-string:
     SyntaxError or silently corrupted code.
4. **Tables**: assert `len(cols) == len(headers) + 1` and that each header fits
   its column width — a boundary-count mismatch makes headers overlap while
   the row data still looks fine.
5. **Verify page by page before delivery**: render each final PDF page at
   ~110 dpi (`get_pixmap(dpi=110)`) and check with `vision_analyze` for
   clipping at edges, overlapping headers, and missing table rows. For a map
   page, also crop top/bottom and confirm first/last stops are fully visible.
