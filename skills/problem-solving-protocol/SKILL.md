# Problem Solving Protocol (Протокол решения проблем)

**ТРИГГЕР:** Загружать этот навык при возникновении сложных технических неисправностей, багов, тайм-аутов или когда стандартные действия не помогают. Также загружать, если пользователь говорит "хватит перебирать" или "ты мельтешишь".

## 🚫 ЧАСТЬ 1: КАК НЕЛЬЗЯ (Анти-паттерны)
1.  **Запрещён «Слепой перебор»:** Менять параметры наугад без гипотезы.
2.  **Запрещено «Лечить симптомы вместо болезни»:** Не менять IP/порт, если ошибка на уровне протокола (TLS/Handshake).
3.  **Запрещено игнорировать логи:** Если лог пишет ошибку рукопожатия — не трогать настройки клиента до исправления сервера.
4.  **Запрещена «Слепая вера в стандарты»:** Проверять актуальность "стандартных" конфигов на наличие багов в текущей версии ПО (GitHub Issues).
5.  **Запрещено скрывать неопределённость:** Если причина неизвестна — честно сказать и перейти к исследованию, а не гадать.

## ✅ ЧАСТЬ 2: СТРАТЕГИЯ И ТАКТИКА
1.  **Диагностика до лечения (Diagnosis First):** Определить точную точку сбоя (Сеть → TCP → TLS/Handshake → Приложение). Лечить только её.
2.  **Версионный аудит (Version Awareness):** При странной ошибке сразу проверить: «Есть ли известные баги в *этой версии* софта?». Искать по GitHub Issues/Forum.
3.  **Глубокое исследование при тупике (Deep Research):** Если два решения не сработали — СТОП. Переход в режим OSINT (форумы, блоги, исходный код). Не изобретать велосипед.
4.  **Изоляция переменных:** Менять только одну вещь за раз. Если не помогло — откатываться назад перед следующим шагом.
5.  **Слушать стоп-сигналы:** Если пользователь говорит "хватит", немедленно прекратить текущую тактику и сменить её на исследование.

## ПРИМЕР (Урок из практики)
*Ошибка:* Xray Reality handshake failed.
*Неправильно:* Менять flow, fingerprint, порты наугад.
*Правильно:* Читать лог (`handshake did not complete successfully`) → Проверить версию Xray → Найти Issue #6356 (Microsoft cert > 8192 bytes) → Сменить dest на Cloudflare.
